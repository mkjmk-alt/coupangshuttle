# AdSense 승인 준비 콘텐츠·신뢰성 보강 설계

**요청 ID:** 2jXaRBNtdl

## 목표

물류센터 셔틀맵이 단순 노선 데이터 목록이 아니라, 이용자가 노선을 이해하고 안전하게 참고할 수 있는 독창적인 안내 서비스로 인식되도록 콘텐츠·운영 공개·검색 노출 구조를 보강한다. 기존 노선 조회, 정류장 안내, 지도, 비교, 광고 동의, 관리자 기능은 유지한다.

## 범위

- `/guide`: 서비스 소개, 노선 조회 방법, 정류장 읽는 방법, 탑승 전 확인, 데이터 출처와 한계를 설명하는 원본 안내 페이지
- `/faq`: 반복 문의를 줄이는 원본 FAQ 페이지
- 기존 홈과 푸터에 가이드·FAQ·운영 정책의 진입 링크 추가
- 운영 및 데이터 정책에 출처·검수·정보 불일치 처리 기준 추가
- `robots.txt`, `sitemap.xml`, 사이트 canonical과 `metadataBase` 추가
- 모바일 내비게이션은 조회·정류장·문의 3개를 유지하고, 가이드·FAQ는 데스크톱 메뉴와 푸터에서 접근

## 콘텐츠 원칙

- 실제 서비스 흐름과 현재 데이터 구조를 기준으로 직접 작성한다.
- 센터별 페이지를 자동 생성해 비슷한 문장을 반복하지 않는다.
- 쿠팡 공식 서비스처럼 보이게 하지 않으며 공식 공지 우선 원칙을 모든 관련 안내에 표시한다.
- 운행을 보장하거나 실시간성을 암시하지 않는다.
- 날짜와 데이터 의미를 운영 정책과 연결한다.

## 기술 설계

- App Router의 서버 페이지로 정적 콘텐츠를 제공한다.
- `app/robots.ts`는 canonical 호스트를 허용하고 sitemap URL을 제공한다.
- `app/sitemap.ts`는 공개 안내·정책·조회 페이지를 고정 URL로 반환한다.
- `app/layout.tsx`의 `metadataBase`와 `alternates.canonical`을 canonical 호스트에 맞춘다. 소셜 미리보기 이미지는 새로 만들지 않는다.
- 검증 스크립트는 파일 존재, 핵심 원본 문구, 링크, 검색 파일을 검사하며 브라우저나 외부 API에 의존하지 않는다.

## 완료 기준

1. 가이드와 FAQ가 실제 페이지로 열리고 관련 메뉴·푸터에서 접근된다.
2. 운영 정책에 데이터 출처와 오류·불일치 처리 원칙이 명시된다.
3. `robots.txt`와 `sitemap.xml`이 생성되며 canonical 메타데이터가 설정된다.
4. 새 검증 테스트, TypeScript, ESLint, Next 빌드, 기존 정류장 데이터 테스트가 모두 통과한다.
5. 변경사항을 GitHub `main`에 저장하고 Cloudflare Pages 공개 주소에 반영한다.

# AdSense 콘텐츠·신뢰성 보강 설계

## 목적

새 공개 배포본의 핵심 이용 가치를 유지하면서 Google AdSense 검토에 필요한 원본 콘텐츠, 검색 가능한 정보 구조, 데이터 최신성·검수 안내, 개인정보·제휴 고지를 보강한다. 노선 조회와 정류장 조회의 기존 기능은 유지하고, 실제로 확인되지 않은 데이터나 최신 날짜를 임의로 만들어 내지 않는다.

## 현재 문제와 판단

- 공개 페이지와 기본 SEO 요소는 갖추었지만, 노선 상세 데이터가 사용자의 선택 이후 브라우저에서 로드되어 검색봇이 전체 내용을 직접 읽기 어렵다.
- `public/data/shuttle_meta.json`의 최신 데이터 시각은 `2026-07-25 21:04`이며, 현재 데이터가 오래된 경우 화면에서 명확히 알릴 장치가 없다.
- 변경 로그에는 좌표·이동거리 검수 대상이 포함될 수 있지만 일반 이용자가 확인할 수 있는 요약 화면이 없다.
- 개인정보·쿠키 설정과 제휴 고지는 존재하지만, AdSense 신청 전 확인해야 할 운영 체크리스트가 흩어져 있다.

## 사용자 경험과 정보 구조

### 1. 센터 디렉터리

`/centers`를 추가한다.

- 98개 센터를 센터명·코드·지역으로 검색할 수 있다.
- 각 항목에는 센터 상세 페이지와 현재 정류장 조회 링크를 제공한다.
- 센터별 데이터가 없거나 로드에 실패하면 빈 결과를 정상 상태로 설명한다.

### 2. 서버 렌더링 센터 상세 페이지

`/centers/[code]`를 추가한다.

- 빌드 시 `public/data/centers/*.json`을 읽어 정적 페이지를 생성한다.
- 센터명, 주소, 근무조 수, 노선 수, 정류장 수, 데이터 확인 시각을 본문에 포함한다.
- 근무조별 노선명과 정류장 수를 요약하되, 모든 원본 정류장 상세를 반복 렌더링하지 않는다.
- 실제 조회 기능은 기존 `/stops`로 연결하고 센터 코드를 query parameter로 전달한다.
- 센터별 `title`, `description`, `canonical`을 생성한다.
- 데이터가 존재하지 않는 코드에는 404를 반환한다.

### 3. 공개 변경 이력

`/updates`를 추가한다.

- `public/data/shuttle_changelog.json`에서 안전한 요약 필드만 읽는다.
- 최근 변경 일시, 자동·수동 구분, 영향 센터, 노선·정류장 변경 수를 표시한다.
- 좌표·주소 등 변경 전후 원본과 외부 이미지 URL, 관리자용 세부값은 공개하지 않는다.
- 변경 이력이 없을 때도 빈 상태 설명을 제공한다.

### 4. 기존 설명 페이지 보강

- 홈, 가이드, FAQ, 운영 정책, 문의 페이지에 센터 디렉터리·변경 이력 링크를 추가한다.
- 운영 정책에는 데이터 기준일, 검수 상태, 제보 후 처리 흐름을 실제 운영 기준으로 설명한다.
- 영어 장식 문구와 반복적인 홍보 표현은 추가하지 않는다.

## 데이터 신뢰성과 품질 안내

### 1. 공통 데이터 요약

`utils/dataSummary.ts`를 추가해 센터 JSON에서 다음을 계산한다.

- 센터명·주소
- 근무조 수
- 노선 수
- 정류장 수
- 데이터 기준 시각
- 검수 경고 수

화면과 테스트는 이 요약 함수를 사용해 서로 다른 집계 기준이 생기지 않도록 한다.

### 2. 최신성 경고

- `shuttle_meta.json`의 시각을 기준으로 30일 초과 시 `재확인 필요` 상태를 계산한다.
- 날짜를 임의로 갱신하지 않는다.
- 홈과 센터 상세 페이지에는 짧은 경고를, 운영 정책과 가이드에는 판단 기준을 표시한다.

### 3. 품질 경고

다음 값은 자동으로 검수 대상으로 집계한다.

- 주소·정류장명이 비어 있는 항목
- `None`, `null`, `미정` 등 placeholder가 주소·이름에 남아 있는 항목
- 위도·경도가 유효한 숫자가 아닌 항목
- 같은 노선 안에서 시간이 비정상적으로 역순인 항목
- 변경 로그에 좌표가 바뀌었지만 주소 검수 정보가 없는 항목

경고는 데이터를 숨기거나 삭제하지 않고, 이용자에게 “공식 공지를 우선 확인해 달라”는 안내와 함께 표시한다. 실제 데이터 수정은 확인된 자료가 있을 때만 수행한다.

## AdSense·개인정보·제휴 고지

- 현재 `google-adsense-account` 메타 태그와 `ads.txt`를 유지하고, 사이트 등록·소유권 확인·`Authorized` 상태 확인 절차를 가이드에 정리한다.
- 현재 자체 동의 창을 Google 인증 CMP로 오인하지 않도록 개인정보처리방침에 실제 동작 범위만 설명한다.
- AdSense Privacy & messaging 또는 인증 CMP를 계정에서 설정할 수 있도록 운영 체크리스트를 추가한다. 계정 설정이 필요한 항목은 코드에서 완료된 것처럼 표시하지 않는다.
- 쿠팡 제휴 배너는 `제휴 링크`와 수수료 고지를 명확히 유지하고, 핵심 노선 콘텐츠를 가리지 않도록 배치한다.
- 승인 전에는 광고 영역을 새로 추가하지 않는다. 승인 후 실제 광고 단위와 위치를 별도 검토한다.

## SEO와 연결 구조

- `app/sitemap.ts`에 `/centers`, `/centers/[code]`, `/updates`를 포함한다.
- 센터 페이지의 `lastModified`는 데이터 기준 시각을 사용하고, 현재 시각을 가장하지 않는다.
- 내부 링크는 홈 → 센터 디렉터리 → 센터 상세 → 정류장 안내 흐름으로 연결한다.
- robots와 canonical은 기존 공개 도메인을 유지한다.

## 오류와 접근성

- 센터 목록 로딩 실패, 센터 코드 404, 변경 이력 손상, 오래된 데이터 모두 사용자에게 읽을 수 있는 설명을 제공한다.
- 검색·정렬·링크는 키보드로 접근할 수 있어야 한다.
- 모바일에서도 센터 디렉터리와 가이드·FAQ 링크가 보이도록 한다.

## 테스트와 완료 조건

다음 검증을 구현 전 실패-구현 후 성공 순서로 추가한다.

1. 데이터 요약 함수가 센터·노선·정류장 수를 정확히 집계한다.
2. 최신성 계산이 30일 경계와 잘못된 날짜를 처리한다.
3. 품질 경고가 placeholder·좌표·시간 문제를 감지한다.
4. 센터 디렉터리와 상세 페이지가 유효한 코드만 렌더링하고 잘못된 코드는 404 처리한다.
5. 변경 이력 페이지가 안전한 요약 필드만 노출한다.
6. sitemap에 새 경로와 canonical이 포함된다.
7. TypeScript, ESLint, 전체 빌드, 기존 테스트가 통과한다.
8. 공개 배포 후 홈·센터 디렉터리·센터 상세·변경 이력·정책 페이지가 HTTP 200을 반환한다.

## 범위 밖

- 실제 AdSense 계정 생성·승인 요청·CMP 계정 설정은 사용자 계정 접근이 필요하므로 코드 작업에 포함하지 않는다.
- 새로운 셔틀 원본 자료가 없으면 기존 데이터의 날짜·주소·시간을 추정해 수정하지 않는다.
- 3,656개 모든 노선을 개별 URL로 대량 생성하지 않는다. 우선 센터 단위의 충분한 요약 페이지를 만든다.

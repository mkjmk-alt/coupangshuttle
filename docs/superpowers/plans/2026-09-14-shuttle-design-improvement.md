# 물류센터 셔틀맵 디자인 개선 계획

> 실행 담당: `superpowers:executing-plans`를 참고하여 아래 체크리스트를 순서대로 수행한다. 현재 문서는 계획이며 구현 완료를 의미하지 않는다.

**요청 ID:** D4X8X38VMy

**Goal:** 파스텔 지도 테마의 친근함을 유지하면서 모바일 첫 화면에서 센터 선택을 시작하고, 설명과 운행 정보를 쉽게 읽게 한다.

**Architecture:** 기존 Next.js App Router 구조와 ShuttleExplorer 상태·데이터 흐름을 유지한다. 홈페이지 구성과 이름 있는 CSS 클래스 중심으로 수정하고, 공통 스타일 변경은 정책·문의·관리자 화면에 미치는 영향을 함께 확인한다.

**Tech Stack:** Next.js, React, TypeScript, Tailwind CSS, app/pastel.css. 추가 의존성은 필요하지 않다.

**Spec:** 기존 `design_pastel.md`의 색상·아이콘 보존 원칙과 이 문서의 개선 사양을 따른다. 충돌하는 홈 배치·폰트 크기·브랜드 서체 항목은 이 개선 사양을 우선한다.

## 범위와 원칙

- 브랜드는 `물류센터 셔틀맵`, 홈 제목은 `쿠팡 물류센터 셔틀 노선`을 유지한다.
- 아이보리 배경, 블루 강조, 민트 보조색과 원본 지도·버스 아이콘 구도를 유지한다.
- 이미지 생성·크롭·버스만 추출하는 작업은 포함하지 않는다.
- 노선 데이터, 지도 공급자, 선택·비교 기능, 광고 동의, API, 문의 주소를 변경하지 않는다.
- `design.md`, `design_new.md`는 보존한다. 구현 완료 시 `design_pastel.md`에 확정 사양을 반영한다.
- 기존 미커밋 작업을 유지한다. 계획 작성이나 로컬 구현은 커밋·푸시·배포를 포함하지 않는다.
- 모바일 검색, 최근 조회, 즐겨찾기, 실시간 운행 등 신규 기능은 이번 범위에 넣지 않는다.

## 현재 확인한 문제

1. 620px 이하에서 `.hero-art { order: -1; }`과 144px 아이콘이 제목·조회 영역보다 먼저 나타난다.
2. `.hero-stats`의 세 카드가 조회 전에 별도의 세로 공간을 차지한다.
3. 모바일 설명은 13px, 주의 안내는 11px, 선택 라벨은 10px이다.
4. 브랜드가 본문과 다른 serif 서체를 사용해 작은 한국어 이름의 인상이 불균일하다.
5. 모바일 하단 메뉴 다섯 개 중 개인정보·약관 등 보조 항목의 비중이 크다.

이는 코드·화면 관찰이며 실제 사용자의 조회 시간이나 만족도를 측정한 결과는 아니다.

## 목표 화면 구성

```text
상단: 원본 아이콘 + 물류센터 셔틀맵
짧은 소개: 쿠팡 물류센터 셔틀 노선
설명: 센터·근무조별 정류장과 운행 시각을 확인하세요.
보조: 비공식 노선 안내 · 실제 데이터 업데이트 시각
조회 카드: 물류센터 → 근무조 → 노선
카드 안 안내: 탑승 전 센터의 최신 공식 공지를 확인하세요.
기존 지도·정류장·비교·제휴 영역
도움말 및 정책·문의 링크
```

소개 그림은 데스크톱에서 제목 옆에 작게 남긴다. 모바일에서는 상단 로고의 원본 아이콘을 유지하고 소개 영역의 중복 그림·장식 노선은 숨긴다. 비공식 안내는 소개에, 실제 탑승 주의는 조회 카드에 각각 명시한다.

## 작업 1. 첫 화면을 조회 중심으로 재배치

**파일:** `app/page.tsx`, `components/ShuttleExplorer.tsx`, `app/pastel.css`

- [ ] 수정 전 390×844, 820×1180, 1440×900 화면을 같은 초기 상태로 캡처한다. 첫 센터 선택창의 위치를 기록한다.
- [ ] `app/page.tsx`의 `.hero-stats` 세 카드와 영어 eyebrow, 그림 캡션을 제거한다. 같은 내용을 새 배지 세 개로 다시 만들지 않는다.
- [ ] 소개 문구를 아래 내용으로 구성한다. 업데이트 시각은 기존 메타데이터에서 가져오며 날짜를 직접 입력하지 않는다.

```tsx
<h1 className="display-title">
  쿠팡 물류센터 <span className="text-gradient">셔틀 노선</span>
</h1>
<p className="hero-copy">센터·근무조별 정류장과 운행 시각을 확인하세요.</p>
<p className="hero-service-note">쿠팡 물류센터 근무자를 위한 비공식 노선 안내입니다.</p>
```

- [ ] 업데이트 배지를 제목 앞에서 소개 하단으로 옮긴다. 초록 점을 실시간 운행·정보 정확성 보증처럼 설명하지 않는다.
- [ ] 홈의 별도 큰 주의 박스를 조회 카드 하단으로 옮긴다. 문구는 `노선과 운행 시각은 참고용이며 변경될 수 있습니다. 탑승 전 소속 센터의 최신 공식 공지를 확인해 주세요.`로 한다. 조회 로딩·실패 상태에서도 해당 안내가 사라지지 않도록 각 상태에 동일 문구를 표시한다.
- [ ] 모바일에서는 소개 그림을 숨기고 제목을 왼쪽 정렬한다. 데스크톱 그림은 144~160px로 축소한다. 삭제된 장식의 미사용 CSS를 함께 정리한다.

```css
.home-hero { padding: 24px 0 20px; }
.hero-main { grid-template-columns: minmax(0, 1fr) 160px; gap: 24px; }
.hero-icon { width: 160px; height: 160px; border-radius: 32px; }
@media (max-width: 620px) {
  .home-hero { padding: 20px 0 16px; }
  .hero-main { grid-template-columns: 1fr; text-align: left; }
  .hero-art { display: none; }
}
```

**확인 기준:** 데이터 로딩 완료·동의 창 닫힘·스크롤 최상단·기본 배율 기준 390×844에서 첫 센터 선택창 전체가 고정 하단 메뉴 위에 보인다. 1440×900에서는 센터·근무조·노선 선택 세 개가 첫 화면에 보인다. 글자를 줄여 목표를 맞추지 않는다.

## 작업 2. 가독성과 조회 카드 정리

**파일:** `app/pastel.css`, `components/ShuttleExplorer.tsx`

- [ ] 소개 본문과 선택 값은 16px, 안내·업데이트·라벨은 최소 14px로 정한다. 홈 제목은 모바일 30~34px, 데스크톱 40~48px 범위로 유지한다.
- [ ] 선택 라벨을 `1. 물류센터`, `2. 근무조`, `3. 노선`으로 표시하고 과도한 자간을 없앤다. 각 label의 htmlFor와 select의 id를 `shuttle-center`, `shuttle-shift`, `shuttle-route`로 연결한다.

```tsx
<label htmlFor="shuttle-center" className="route-field-label">1. 물류센터</label>
// 기존 센터 select에 id="shuttle-center"를 추가한다. value와 onChange는 유지한다.
```

- [ ] 조회 section에 `route-search-card`, 선택 grid에 `route-search-fields`를 추가해 전용 스타일로 관리한다. 긴 소개 설명은 `센터, 근무조, 노선을 순서대로 선택해 주세요.`로 단축한다. 비교 기능 안내는 기존 비교 버튼 근처에 둔다.
- [ ] 카드 안쪽 여백은 모바일 20px, 데스크톱 24px, 필드 사이 간격은 16px로 한다. 선택창은 최소 48px 높이로 유지한다.

```css
.hero-copy { font-size: 16px; line-height: 1.65; color: var(--ink); }
.hero-service-note, .update-pill, .route-search-notice {
  font-size: 14px; line-height: 1.6; color: #526270;
}
.route-field-label { font-size: 14px; font-weight: 700; letter-spacing: 0; }
.route-search-card .premium-input { min-height: 48px; font-size: 16px; }
```

- [ ] 작은 본문은 단색 진한 글자를 사용한다. 사용 가능한 입력창의 경계·포커스와 비활성 상태를 구분하고, 실제 배경색과 합성된 글자색으로 대비를 확인한다. 본문 4.5:1, 큰 제목·주요 컨트롤 경계 3:1을 자체 검수 목표로 사용한다.

**확인 기준:** Tab으로 세 선택창과 비교·공식 안내에 접근할 수 있고 연결된 라벨이 읽힌다. 센터 변경 시 하위 선택 초기화 등 기존 동작이 같다. 320px 폭과 200% 확대에서 주요 내용이 잘리지 않는다.

## 작업 3. 브랜드와 내비게이션 선명도

**파일:** `app/layout.tsx`, `components/SiteNavigation.tsx`, `app/pastel.css`

- [ ] 브랜드 글자를 시스템 sans-serif, 18~20px, 굵기 750으로 통일한다. 원본 아이콘은 44~48px로 표시한다. 사이드바에서는 두 줄, 모바일 상단에서는 공간에 맞춰 한 줄로 표시한다.

```css
.brand-name { font-family: var(--font-sans); font-size: 20px; font-weight: 750; line-height: 1.25; }
@media (max-width: 980px) {
  .mobile-topbar .brand-name { font-size: 18px; }
  .mobile-topbar .brand-name em { display: inline; }
}
```

- [ ] 상단의 `ROUTE FINDER` 장식 문구를 제거한다. 모바일 상단 높이는 64px로 조정하고 `.page-shell`의 위쪽 여백도 같이 맞춘다.
- [ ] 모바일 하단 메뉴를 기존 경로의 `노선 조회`, `운영 안내`, `문의·제보` 세 개로 줄인다. 개인정보·약관은 기존 푸터와 데스크톱 메뉴에서 접근 가능하게 유지한다. 새 더보기 메뉴는 만들지 않는다.
- [ ] 문자 기호 아이콘은 컴포넌트 내부의 단순한 선형 SVG로 통일한다. 메뉴 글자는 12~14px, 터치 영역은 최소 48px로 한다. `aria-current`와 안전 영역 여백을 유지한다.

**확인 기준:** 320px에서 로고가 잘리거나 이름이 세 줄로 깨지지 않는다. 메뉴별 현재 페이지 표시가 정확하며 하단 메뉴가 마지막 콘텐츠나 동의 창의 버튼을 가리지 않는다.

## 작업 4. 회귀 검수와 디자인 문서 동기화

**파일:** `design_pastel.md`, `기록-history.md`; 검수 중 발견된 이번 변경의 문제에 한해 위 구현 파일 수정.

- [ ] 320×740, 390×844, 820×1180, 1440×900에서 초기 홈·센터 선택 후 화면을 확인한다. 같은 크기의 전후 캡처를 비교한다.
- [ ] 김해1센터 → 오후조 → 김해3의 조회·정류장 표시, 다른 센터로 변경, 기존 비교 기능, 공식 안내 링크를 확인한다. 광고·동의 관련 검수에서는 외부 광고를 클릭하지 않는다.
- [ ] 로딩·데이터 오류·지도 오류 상태의 안내와 레이아웃을 확인한다. 지도 키 등 환경 문제로 실제 지도를 확인하지 못한 경우 성공으로 기록하지 않고 검증 한계를 별도로 남긴다.
- [ ] 정책·문의·관리자 진입·동의 창에서 공통 CSS로 인한 잘림을 점검한다. 관리자 데이터는 저장하지 않는다.
- [ ] 다음 명령을 실행한다. 순수 문구·CSS 존재 여부만 확인하는 새 테스트는 만들지 않는다.

```bash
npx eslint app/page.tsx app/layout.tsx components/SiteNavigation.tsx components/ShuttleExplorer.tsx
npm run build
git diff --check
```

- [ ] 기존 ShuttleExplorer 린트 오류가 있으면 수정 전 결과와 비교해 신규 문제를 구분한다. build의 prebuild가 생성하는 데이터 파일 diff도 확인한다.
- [ ] 확정된 글자 크기·모바일 이미지 처리·메뉴 구성과 브랜드명을 `design_pastel.md`에 반영한다. `design_new.md`는 작업 전후 해시가 같아야 한다.
- [ ] 요청 ID와 실제 수정·검증 결과를 `기록-history.md`에 추가한다. 비교 스크린샷과 남은 제한을 함께 전달한다.

## 우선순위와 완료 조건

우선 작업 1~2로 조회 접근성과 읽기 편의성을 확보한 다음 작업 3으로 브랜드·메뉴를 정돈한다. 작업 4까지 확인한 로컬 결과를 최종 산출물로 한다.

완료 판단은 주관적인 디자인 점수 상승이 아니라 첫 센터 선택창의 노출, 글자 크기·대비, 화면 잘림 여부와 기존 조회 기능의 정상 작동으로 한다. 실제 조회 시간 개선률은 사용자 테스트 전에는 주장하지 않는다.
